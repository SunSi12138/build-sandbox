# 批量导入（复用现有 API）

批量导入不新增服务端接口，全部复用工具已有的 HTTP API。导入端由 `scripts/batch-import.py`
负责：把材料整理成清单（manifest），压缩图片、按名称解析社区/类型/标签、逐条写入并记录幂等日志。
服务端保持不变，正式版仍是原来的 AOT 程序。

## 工作流

1. **复制材料**到工作目录（例如 `import/work/2026环保/`），原件不动。
2. **抽取文本**：`python scripts/materials-extract.py --source <材料目录> --out <文本目录>`，
   生成 `index.json` 和逐文件的 `text/**.txt`，供分析使用。
3. **分析并生成清单**：分析 agent 按下面的 manifest 结构输出 JSON，一材料一条目，
   不确定的放到 `import/needs-info/`，不要猜造数据。
4. **先试运行**：`apply --dry-run` 只做校验和照片压缩，不写入。
5. **正式导入**：`apply`，每成功一条写入一份 journal，重复执行自动跳过。
6. **复核**：用工具页面或 `GET /api/points`、`/api/inspections` 抽查。

## 命令

```bash
# 查看服务端已有的社区、类型、标签（分析前先跑一次）
python scripts/batch-import.py bootstrap --server http://127.0.0.1:5181

# 试运行（不写库，只验证清单与照片）
python scripts/batch-import.py apply --manifest import/manifests/2026环保.json \
    --server http://127.0.0.1:5181 --dry-run

# 正式导入；默认压缩图片，--no-compress 保留原图
python scripts/batch-import.py apply --manifest import/manifests/2026环保.json \
    --server http://127.0.0.1:5181

# 只导入某一类，或先小批量验证
python scripts/batch-import.py apply --manifest ... --only point,inspection --limit 5

# 旧版本部署目录（含 data/app.db 与 photos/）直接转清单
python scripts/batch-import.py old-db --app-dir import/old-version/环保日常排查整治整改 \
    --source "旧版2026-10" --out import/manifests/old-version.json
```

字段约定：

- `kind` 取 `point` / `inspection` / `activity` / `campaign` / `matter`。
- `key` 全局唯一，用于幂等；建议 `<材料来源>/<日期>-<要点>`。
- 社区、点位类型、问题类型、活动类型、整治类别、标签都写**名称**，工具自动解析或创建。
- 日期接受 `2026-03-24`、`2026/3/24`、`2026年3月24日`，统一转成 `yyyy-MM-dd`。
- 点位照片最多 9 张；排查现场照片最多 20 张；活动照片最多 20 张；整治按前/中/后分组。
- 排查的问题没写期限时，工具按排查日期 +7 天处理，并在报告里给出警告。
- `campaign` 的点位必填（整治记录必须挂在点位上）。

## 图片压缩

- 默认压缩：长边缩到 1600、质量取设置里的 `jpegQuality`（默认 75），由导入端 Pillow 完成，
  与服务端“照片在客户端压缩后再上传”的既有架构一致；单个文件上限 10 MB。
- `--no-compress` 或条目里 `"compress": false` 时按原图字节写入。
- 压缩只发生在导入副本上，不改动材料原件。

## 幂等与报告

- 每次成功写入立即更新 `<manifest>.journal.json`；重复执行会跳过已完成条目。
- 输出包含 `created / skipped / failed / photos` 统计、逐条错误和警告；有错误时退出码为 1，
  修完清单可安全重跑。
- 清单本身建议纳入版本管理；journal 可删除以强制重导（会重复建记录，慎用）。
