# 文案、操作与前端优化

> 历史实施记录。当前功能与数据结构以 [新版使用说明](new-application.md) 为准。

日期：2026-10-23。基于 `5a0f047` 的活动升级分支继续完善，数据库结构保持版本 1。

## 本轮已完成

### 人员与单位

- 人员输入改用已有 Nuxt UI 的 `UInputTags`；外层保留字符串字段适配、中文输入法处理、总长度约束，以及未按回车的文字保存。
- 标签文字与删除按钮使用统一背景和高度，手机点击区域至少 40×40。默认排查人使用整行输入。
- 列表和详情用普通文字分隔姓名、单位。排查列表最多显示前两项，长内容在表格单行省略，详情保持完整。
- 分隔支持逗号、顿号、分号、空白及换行；句点和句号保留为名称内容，`Dr.Li` 不再被拆开。

### 活动录入

- 编辑已有活动时，返回、取消或切换页面会提示未保存修改；刷新/关闭页签有浏览器原生提示。保存期间禁止离开，照片上传未完成时有单独提示。
- 新建草稿延迟写入浏览器存储，离开页面时立即补存。保存成功清除对应草稿，避免重复恢复。
- 主要填写项保留在前；结束日期、参加人员和人数、成效、备注放入“更多信息”。编辑已有记录或恢复带有这些内容的草稿时自动展开。
- “全部社区或跨社区”简化为“跨社区”，“活动内容及开展情况”简化为“开展情况”。

### 筛选与导出

- 排查列表增加问题类型筛选。手机首屏显示社区和问题类型，点位类型与日期放入展开筛选，保留列表阅读空间。
- 排查、整治、活动列表默认按当前筛选导出，覆盖全部匹配记录，不限当前分页；可切换自定义范围。
- 弹窗显示范围摘要与预计记录数；整改台账显示问题数。搜索词、类型、状态、点位等条件由服务端实际过滤。
- 同一排查包含多类问题时，问题类型与逾期/待复查条件必须命中同一问题；列表问题数与整改导出采用同一逻辑。
- 三种列表的日期快捷项统一为本月、上月、本季、本年、自定义。活动导出按钮统一为“导出 Word”。
- 搜索延迟 250ms 请求，取消过时的列表请求。搜索后立即导出会先提交最新筛选，避免导出上一次结果。
- 重复的 URL 查询参数按列表相同规则取首值，不会使导出范围意外扩大。

### 设置与文案

- 社区、点位类型、问题类型、整治类型、活动类型改为分组切换；较长字典可以搜索。
- 照片清晰度提供节省空间、标准、清晰和自定义；精确数值放入高级设置，保留已有自定义值。
- 通知单示例折叠；“监听地址”改为“访问设置”；“每日数据库快照”改为“自动备份（不含照片）”。
- 删除不可恢复、上传中断及备份范围等影响操作判断的提示保留。
- 修复设置分组与链接参数、浏览器导航不同步的问题。

## 额外功能分析：后续建议，尚未实施

### 1. 从历史记录新建、常用内容片段 — 优先

工作部署、宣传学习和常规整治会重复填写地点、组织单位和类似内容。可以在历史记录增加“以此新建”，带入名称、类型、地点、人员和正文草稿，日期重新选择，照片按本次实际情况添加。再根据实际使用频率决定是否需要独立的内容模板管理。

价值：直接减少日常录入时间，比增加首页统计卡片更容易感知。

### 2. 录入前提示已有问题与疑似重复点位 — 优先

当前新建点位没有业务上的相似性提示，新排查也没有集中呈现该点位仍未闭环的问题。建议：

- 选中点位后显示“仍有 X 项问题未闭环”，可直接查看或继续反馈。
- 新建点位时，按社区、名称、地址提示疑似已有点位，用户可选择已有记录或确认继续新建。

价值：减少重复点位、同一问题反复登记和后续统计失真。点位匹配应先采用简单规则，已有重复数据的合并需另做关联检查。

### 3. 完整备份提醒 — 优先

当前每日自动备份只有数据库，照片依靠完整 ZIP。建议显示最近一次完整备份的生成时间，长时间未生成时给出轻量提醒，并提供直接下载入口。自动生成完整备份可作为后续选项，需同时设置保留份数、可用空间检查和失败提示。

价值：符合“留痕工具”的主要用途。生成成功、下载成功和已保存到另一设备是不同状态，界面应区分。

### 4. 月度汇总及表格导出 — 有固定上报任务时优先

现有 Word 台账适合打印留档，跨社区汇总仍需人工整理。可提供按月/季度的排查次数、涉及点位、问题分类、整治次数、活动次数及参与人次，并增加 Excel/CSV 导出。

先确定统计口径：本期发现的问题、本期完成的闭环、期末未闭环存量分别展示；多场活动相加应称“人次”，不能声称已经去重为“人数”。

### 5. 多端编辑冲突提示 — 多人使用时提高优先级

当前保存记录没有版本冲突令牌。若两部手机同时编辑同一记录，后提交的内容可能覆盖先前修改。可在保存前检查版本变化，提示刷新或对比修改；这项能力可以独立于登录和权限系统实施。

## 建议顺序

先做历史复用、已有问题/重复点位提示和完整备份提醒。确有固定上报工作再加月度汇总；出现多人同时录入后再提高编辑冲突处理的优先级。
